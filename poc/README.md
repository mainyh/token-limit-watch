# Token Limit Watch PoC — 사용량 조회 경로 검증

기획서 10장의 남은 결정 1번(조회 경로)을 확인하는 PoC입니다.
같은 로그인 세션으로 두 방식을 비교합니다.

## 제품 표시 범위

최종 앱의 서비스 카드에는 다음 네 가지 정보만 표시합니다.

1. 사용량: 현재 사용률 또는 사용량
2. 남은량: 한도 대비 남은 비율 또는 남은 수량
3. 초기화 시간: 초기화 예정 시각
4. 초기화까지 남은 시간: 현재 시각 기준 카운트다운

조직 수, 인증 API 상태, 조회 방식, 응답 키 개수 같은 값은 진단 로그에만 남기고 사용자 화면에는 표시하지 않습니다. 서비스 응답에 값이 없으면 추정하지 않고 `확인 불가`로 표시합니다.

| 방식 | 동작 |
| --- | --- |
| A 브라우저 fetch | 화면 밖에 띄운 WebView2가 서비스 페이지를 연 뒤, 그 페이지 안에서 `fetch()`로 조회 |
| B HttpClient | WebView2 프로필의 쿠키와 User-Agent를 꺼내 HttpClient로 직접 조회 |

## 실행

```powershell
dotnet run --project poc\TokenLimitWatch.Poc
```

1. 서비스별 **로그인**을 눌러 이메일 계정으로 로그인합니다. 세션 쿠키가 확인되면 창이 자동으로 닫힙니다. Google 계정 로그인은 막혀 있습니다.
2. **A 조회**, **B 조회**로 한 번씩 확인합니다.
3. **A·B 반복 비교**로 여러 번 돌려 성공률과 차단 횟수를 봅니다. 반복 횟수와 간격은 상단에서 바꿉니다.
4. Cloudflare 확인 화면이 의심되면 **숨긴 브라우저 창 보기**를 켜서 직접 봅니다.

## 서비스별 확인 내용

| 서비스 | 요청 | 성공 조건 |
| --- | --- | --- |
| Claude | `/api/organizations` → `/api/organizations/{org}/usage` | 사용량 응답에서 `utilization`과 `resets_at` 필드를 읽음 |
| ChatGPT | `/api/auth/session` → `poc-config.json`의 `extraEndpoints` (Bearer 토큰) | 인증 API가 200으로 응답함. 한도 관련으로 보이는 키를 로그에 기록 |

ChatGPT는 남은 횟수를 표시하지 않는 기존 결정에서 변경하여, 최종 앱에서는 사용량·남은량·초기화 시간·카운트다운을 표시할 수 있는 데이터만 사용합니다. 현재 PoC 엔드포인트에서는 이 4개 값을 확인하지 못했으므로, 실제 사용량/한도 응답을 찾기 전까지 ChatGPT 카드는 `확인 불가` 상태로 표시해야 합니다. 후보 엔드포인트는 `poc-config.json`에 추가하면 됩니다(빌드 결과 폴더의 사본을 고쳐도 됩니다).

## 결과 파일

- `bin\...\data\poc-results.jsonl`: 실행 1회당 1줄입니다. 경로, HTTP 상태, 응답 시간, 차단 여부, 응답 구조가 들어갑니다.
- 응답 구조에서 토큰, 이메일, 이름, ID 같은 문자열은 `<string:길이>`로 가려집니다. 숫자와 한도 관련 키(`limit`, `reset`, `utilization` 등)만 남깁니다.
- `data\webview2\`에는 로그인 세션이 들어 있습니다. 공유하거나 커밋하지 마세요(`.gitignore`에 포함).

## 판정 기준 (PoC 게이트)

| 결과 | 결정 |
| --- | --- |
| B가 반복 실행에서 차단 없이 성공 | B를 기본으로 사용(가볍고 빠름). A는 차단될 때의 대체 수단 |
| B가 차단되고 A는 성공 | A를 기본으로 사용. 조회할 때만 WebView2를 띄워 메모리 목표를 지킴 |
| 둘 다 실패 | 해당 서비스는 1차 범위에서 제외하거나 조회 방식을 다시 조사 |

한 서비스당 최소 10회 반복, 시간대를 바꿔 2회 이상 측정한 결과로 판정하는 것을 권장합니다.

## 2026-11-23 최종 PoC 측정 결과

서비스별 10회 반복 측정 결과입니다.

| 서비스 | A 브라우저 fetch | B HttpClient | 1차 판단 |
| --- | --- | --- | --- |
| Claude | 10/10 성공, 평균 570ms | 0/10 성공, 10회 HTTP 403 차단 | A를 기본 경로로 확정 |
| ChatGPT | 10/10 성공, 평균 1,161ms | 10/10 성공, 평균 1,069ms | B를 기본 경로로 확정 |

- Claude의 `five_hour.resets_at`은 `null`이어서 5시간 한도의 초기화 시각은 표시할 수 없습니다. 주간 한도는 정상적으로 `2026-11-25 16:59(KST)`로 읽혔습니다.
- ChatGPT는 인증 API 2/2가 성공했고 한도 관련 키 22개를 발견했지만, 남은 횟수는 제품 범위에서 제외합니다. 한도 도달 여부와 초기화 시각을 실제로 판정할 수 있는 별도 응답은 아직 확인되지 않았습니다.
- Claude는 10회 모두 브라우저 fetch가 성공했고 HttpClient는 10회 모두 Cloudflare에 차단됐습니다. Claude는 A 기본, B 제외가 적절합니다.
- ChatGPT는 두 방식 모두 10회 성공했습니다. 평균 응답 시간이 더 짧고 WebView2 상주를 줄일 수 있는 B(HttpClient)를 기본으로 하고 A를 대체 경로로 둡니다.
- ChatGPT의 이번 엔드포인트(`/api/auth/session`, `/backend-api/me`, `/backend-api/models`)는 인증과 모델 목록 확인용입니다. 사용량·남은량·초기화 시각 데이터는 아직 발견되지 않았습니다.
